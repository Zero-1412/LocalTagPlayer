# 2026-09-05 扫描提交接续查询与构建成本修复

## 根因与先红后绿

基线 a163098。历史复现见 `phase_frames_and_upgrade_acceptance_20260905.md`：
扫描提交 dataRevision 19→20 后，旧候选被 epoch 校验拒绝，最新输入一直没有发布。
`applyLibraryScanDelta` 对零 changedVideos 提前返回，但 repository 的成功提交仍推进
dataRevision，遗漏了当前 pending 输入的重新调度。

页面级测试点击真实重新扫描入口，挂起 alpha 候选；分别保持 alpha 和继续输入 beta，
再推进 repository revision、提交零差量，最后释放旧候选。修复前两项均失败：
Expected alpha/beta，Actual 空字符串（`ltp_pending_red3.log`）。修复后新结果与当前
epoch 一致，旧 Future 晚到不改变 stable-ID 集合，标签计数调用次数不增加。
新增页面测试加入 core-regression PR/push 门禁，不依靠源码字符串判断正确性。

## 最小改动与受保护行为

- 零差量只在结果 epoch 与当前输入不一致时重新调度；同条件允许空差量复用结果。
- LibraryQueryController 的请求代次、epoch、dispose、缓存与诊断前检查均未修改。
- 扫描进度通过局部 notifier 更新顶部栏；开始/结束、暂停/继续、取消仍更新必要状态。
  页面测试验证进度文字确实更新，同时结果 Widget 仍是原实例。
- 标签面板只缓存一次页面构建内的内容；原 AnimatedContainer、AnimatedSwitcher、
  OverflowBox、展开/收起 key、过渡曲线、恢复按钮及标签回调全部保留。
- 单纯缓存标签内容的 full1 没有改善动画 build P95（26.174 ms，历史 23.872 ms），
  因此继续处理旁侧网格：一次 LibraryVideoGridLayout 数据构建内复用可见卡片，
  约束动画只布局，新数据构建清空缓存。组件测试验证宽度变化保留原卡片实例与列数，
  反转过滤快照后首卡与其 onOpen 来源队列都更新；卡片菜单子树和 callback 未移除。
  缓存最多 200 项，超出后淘汰最早条目，避免长时间滚动保留全库 Widget。
- 索引使用同一事务的 INSERT SELECT，消除全库聚合文本往返 Dart；不引入增量索引、
  schema migration 或后台预热。JSON 解码、失败回滚、完整查询回退及重试保留。
- 搜索 controller、排序、路径返回、卡片菜单、标签筛选、filtered playback queue、
  manual 标签、收藏、进度和真实媒体文件受保护；未授权删除项：无。
