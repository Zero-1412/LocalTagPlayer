# NVIDIA VSR/HDR 自动让路与激活验证

日期：2026-07-28

## 目标

验证 NVIDIA RTX 视频超分和 RTX Video HDR 在现有压缩画质增强、暗场增强开启
时仍可安全请求，并在关闭或回滚后归还 CPU 滤镜所有权。NVIDIA App 的全局状态
不作为播放器运行时真值。

## 实现边界

- 只有压缩画质增强或暗场增强冲突时允许会话级自动让路。
- 固定 mpv 版本、Windows 原生 `gpu-next/D3D11`、`d3d11va`、GPU 和源信号等
  硬门禁保持不变。
- 自动让路不写回用户持久设置；关闭、驱动拒绝或性能回滚后重新采样。
- VSR/HDR 是否实际工作分别由固定 mpv 日志归一化为 `active`，不读取或修改
  NVIDIA App 的全局配置。

## 真实片源结果

三组均为 20 秒真实低码率 1080P，会话同时请求 VSR 与 TrueHDR，并强制预置
压缩清晰增强和暗场增强冲突。

| 片源 | VSR | HDR | 最大总掉帧 | 视频停滞 | 音频停滞 | 回滚 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| 真人面部 | active | active | 0 | 0 | 0 | 无 |
| 动画渐变 | active | active | 0 | 0 | 0 | 无 |
| 暗场 | active | active | 0 | 0 | 0 | 无 |

真人面部组还在性能采样完成后依次关闭 HDR/VSR，确认互斥诊断恢复为“未触发”、
持久压缩档仍为“清晰增强”，且 `vf` 不再包含 NVIDIA VSR/TrueHDR 参数。

## 生命周期观察

首次补充复测在播放器构造早期出现一次 Windows 原生 `0xc0000005`，尚未进入
NVIDIA 请求；同条件立即重跑、动画组和暗场组均通过。该孤例与项目既有 child
HWND 启动抖动一致，当前没有证据把它归因于 NVIDIA 滤镜，仍保留为 Windows
生命周期风险。

## 结论

两个入口可用，不应删除。产品可以在自身播放链中主动请求 NVIDIA 驱动并提供
可靠诊断，但不能保证 NVIDIA App 状态页一定把第三方嵌入式 mpv 会话显示为
“已激活”。默认关闭、仅会话保存和安全回滚保持不变。
