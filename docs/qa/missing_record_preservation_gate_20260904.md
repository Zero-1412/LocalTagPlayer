# Missing 记录保留门禁（2026-09-04）

## 事故根因

历史设置把 `autoRemoveMissingOrUnreadableVideos` 默认设为开启，并在启动首帧、扫描完成和
播放路径预检三个入口读取。Repository 清理会删除视频行、标签关联和备份快照，因此移动硬盘
临时断开、挂载延迟或权限异常可能被误判为永久删除授权。

## 修复合同

- 启动和扫描不得调用 `removeMissingOrUnreadableVideos`。
- 播放预检失败只写入 `isMissing = true`，写入失败必须回滚内存状态并显示错误。
- `videoId`、fingerprint、manual 标签、收藏、播放记录和进度继续绑定原稳定身份。
- 设置页只提供手动“检查并清理”；确认框必须说明用户数据与备份快照会被永久移除。
- 显式清理不删除磁盘文件；移动硬盘断开或权限异常时应取消并先恢复连接。

## 回归路径

1. 使用含 manual 标签、收藏和播放进度的视频库启动应用。
2. 临时断开该 root 所在驱动器，分别执行启动、扫描和点击播放。
3. 确认记录显示 missing，重启后 `videoId` 与用户数据仍存在，且可进入重新关联流程。
4. 打开“设置 → 删除文件 → 检查并清理”，确认未确认时无 Repository 删除调用。
5. 阅读确认框后取消，恢复驱动器并重新扫描；记录应恢复而不是创建第二个身份。

原生窗口自动化不可用时，必须保留 focused widget/code guard、全量测试、analyze 和 Windows
Debug 构建结果，并把上述真实窗口路径标记为未执行，不能写成通过。

同日已补 Windows Flutter surface 门禁与四张 PNG，详见
`docs/qa/library_recovery_visual_gate_20260904.md`；它不替代仍不可用的 SendInput/UIA 与系统
文件选择器证据。

## 同轮恢复性与性能门禁

- 首屏加载必须能从受控失败进入错误页，并由“重新加载”恢复到 ready。
- 收藏命令在 Repository 失败后恢复旧 `isFavorite`，主媒体库和播放器都显示失败反馈。
- 空库主入口选择目录并解释前两级 folder 标签；单文件入口继续保留。
- 筛选零结果同时提供“清除全部筛选”和“查看筛选条件”。
- 11,000 项侧栏统计在同一 revision 只遍历一次；基准记录耗时与 rebuild 次数，不记录路径。
- 依赖只允许在 Flutter 3.47 基线上逐项升级；本轮仅接受两个补丁版本，主版本候选延期。
