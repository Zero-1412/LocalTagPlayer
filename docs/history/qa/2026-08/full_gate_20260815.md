# 2026-08-15 · 播放器资源、全屏与压力门禁复跑

## 结论

本轮完成了显式隔离 profile、Profile/release-like 构建和桌面控制下的重点门禁。MediaKit 长播资源持续增长未能复现为单调泄漏：播放器退出均完成真实原生释放，Windows MediaKit 的固定原生销毁等待约 5.2 秒，纹理最终为 `-1`，释放阶段为 `released`。

全屏卡住是测试时序问题：生产全屏状态机在命令前等待 `endOfFrame`，测试直接 `await` 而没有泵帧，形成死等。矩阵和真实桌面实点均改为/验证了泵帧后执行；桌面控制完成全屏进入、Escape 退出，来源队列仍显示 `1 / 11234`。

## 诊断与修正

- 增删压力先等待专项控制注册、`videoCount > 0 && visibleCount > 0`，再等待连续三帧可见播放入口；修正过期的 smoke key 和已不存在的设置页诊断入口，改用播放器页面诊断快照。
- Profile 构建以前因 `kDebugMode` 和 `assert` 内注册而无法使用压力控制。现在只有 Debug/Profile 且显式传入压力 root 时注册；Release 仍保持不可用。
- 双后端 runner 增加 Profile 路径和 MPV preflight。当前 Windows 的 MPV 报告为 `available`、`mpv_texture_ready`、`libmpv-angle-d3d11`，原生 MPV texture focused test 也通过；macOS/Linux 仍标记为 native backend 未实现，不纳入当前平台可测结论。

AXTree warning 的对照结果：带桌面控制的真实窗口日志复现 188 条 Flutter accessibility bridge AXTree 错误，只有 `Failed to update ui::AXTree`；不接桌面控制、使用另一个独立 profile 的对照启动为 0 条 stderr 错误。它与大语义树 hydration/Route/播放器切换和外部 accessibility observer 的异步 stale-node 更新相关，当前归类为 Flutter Windows/桌面控制环境告警，不是播放器崩溃或释放失败。保留卡片语义、播放器 `BlockSemantics`/页面挂载，不移除无障碍入口。
