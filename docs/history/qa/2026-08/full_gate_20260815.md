# 2026-08-15 · 播放器资源、全屏与压力门禁复跑

## 结论

本轮完成了显式隔离 profile、Profile/release-like 构建和桌面控制下的重点门禁。MediaKit 长播资源持续增长未能复现为单调泄漏：播放器退出均完成真实原生释放，Windows MediaKit 的固定原生销毁等待约 5.2 秒，纹理最终为 `-1`，释放阶段为 `released`。

全屏卡住是测试时序问题：生产全屏状态机在命令前等待 `endOfFrame`，测试直接 `await` 而没有泵帧，形成死等。矩阵和真实桌面实点均改为/验证了泵帧后执行；桌面控制完成全屏进入、Escape 退出，来源队列仍显示 `1 / 11234`。

## 诊断与修正

- 增删压力先等待专项控制注册、`videoCount > 0 && visibleCount > 0`，再等待连续三帧可见播放入口；修正过期的 smoke key 和已不存在的设置页诊断入口，改用播放器页面诊断快照。
- Profile 构建以前因 `kDebugMode` 和 `assert` 内注册而无法使用压力控制。现在只有 Debug/Profile 且显式传入压力 root 时注册；Release 仍保持不可用。
- 双后端 runner 增加 Profile 路径和 MPV preflight。当前 Windows 的 MPV 报告为 `available`、`mpv_texture_ready`、`libmpv-angle-d3d11`，原生 MPV texture focused test 也通过；macOS/Linux 仍标记为 native backend 未实现，不纳入当前平台可测结论。

AXTree warning 的对照结果：带桌面控制的真实窗口日志复现 188 条 Flutter accessibility bridge AXTree 错误，只有 `Failed to update ui::AXTree`；不接桌面控制、使用另一个独立 profile 的对照启动为 0 条 stderr 错误。它与大语义树 hydration/Route/播放器切换和外部 accessibility observer 的异步 stale-node 更新相关，当前归类为 Flutter Windows/桌面控制环境告警，不是播放器崩溃或释放失败。保留卡片语义、播放器 `BlockSemantics`/页面挂载，不移除无障碍入口。

## AXTree 与真实跨 DPI 后续

当前机器只有一块 `DISPLAY1`（2560×1440），因此真实跨物理 DPI 门禁仍为 `pending-physical-cross-dpi`。第二显示器可用后，
必须确认两块屏缩放不同，并实际把同一窗口移入/移出第二屏；仅传入 runner 的 `-PhysicalCrossDpiStatus passed`
不是硬件证据。

AXTree 对照已经形成两层证据：主应用同一大语义树/独立 profile，桌面控制附着时 stderr 有 188 条
`Failed to update ui::AXTree`，无桌面控制时为 0 条。当前 Flutter 3.44.4 的引擎在
`accessibility_bridge.cc:114` 对 `ui::AXTree::Unserialize` 错误统一记录该日志。建议下一步：

1. 用小于当前大库的语义节点数复现“hydration → route 切换 → observer 读取”的最小 Flutter Windows 工程，
   分别运行无 observer、桌面控制 observer 两组。
2. 在隔离 SDK/engine checkout 上 A/B 当前 3.44.4 与候选稳定版本；只有错误在最小工程中随引擎版本消失时，
   才把 SDK/engine 升级作为修复候选。
3. 在证据明确前保留现有 `Semantics`、`ExcludeSemantics`、播放器 `BlockSemantics` 和页面挂载，不以删除
   无障碍树来压低日志计数。

本轮已执行上述最小复现与隔离 A/B：800 个全部挂载语义节点、24 次无动画 route replacement 的 harness
在 Flutter 3.44.4/engine `a10d8ac...` 和隔离 Flutter 3.41.9/engine `42d3d75...` 上，桌面 observer
与无 observer 四组均为 0 条 AXTree/其它 stderr 错误。详细矩阵、运行目录和下一步分层扩展记录于
`docs/history/qa/2026-08/ax_tree_repro_ab_20260815.md`；当前结果是“最小 harness 未复现”，不是 SDK
升级已修复。

分层扩展也已完成：240 个媒体卡片、滚动脉冲、`BlockSemantics` 播放器 route、24 项来源队列和自动
返回媒体库，在同一四格矩阵中仍为 0 条 AXTree/其它 stderr 错误；observer state 实际看到播放器、队列
和返回节点。真实跨 DPI 仍因只有 `DISPLAY1` 阻塞，未运行稳定性矩阵，未写入 `passed`。
