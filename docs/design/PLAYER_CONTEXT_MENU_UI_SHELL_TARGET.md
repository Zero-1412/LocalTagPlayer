# 播放器上下文菜单 UI 外壳目标

本页是播放器 Phase 2 在文件动作弹窗之后的下一处浮层收口。上下文菜单仍只负责把用户带到视频信息和播放诊断；本轮只统一菜单表面、语义和挂载证据，不改变播放器状态或入口动作。

## Before / After

| Before | After | Why |
| --- | --- | --- |
| 菜单只通过当前路由隐式继承 `PopupMenuTheme`，离开播放器上下文时难以确认其表面来源 | 显式使用播放器局部菜单颜色、elevation 和描边形状，并提供播放器上下文菜单语义 | 让菜单与播放器详情、诊断和文件动作浮层保持同一空间层级 |
| 菜单项只有用于边界测量的临时 `GlobalKey`，缺少稳定回归和读屏定位 | 保留临时 `GlobalKey` 的 overlay 测量职责，同时增加稳定 `ValueKey` 与语义标签 | 不破坏菜单定位时序，并让键盘/辅助技术和 focused 测试能定位具体动作 |
| 自定义 `ListTile` 可能绕过 PopupMenu 的文字色传播，深色菜单在实窗中出现低对比度 | 菜单项的 `ListTile`、`Text` 和 `Icon` 都显式复用播放器正文/次级图标色 | 保证结构主题和子项绘制链路同时满足深色表面的可读性 |
| 菜单项展示结构内联在播放器状态扩展中 | 抽出无状态菜单项构建函数，调用方仍拥有位置、结果和动作分发 | 只整理 UI 展示层，降低后续视觉微调触碰播放器业务 owner 的风险 |

## 保护边界

- `视频信息` 与 `诊断检查` 的返回值、分发顺序、上下文菜单 anchor 和 overlay 遮挡门禁保持不变。
- 不修改 `PlaybackSession`、`PlayerBackend`、来源 `filtered playback queue`、诊断采样、媒体详情读取、缩略图/缓存队列、schema、stable identity 或用户数据。
- 不新增 blur、持续动画、查询、I/O 或播放器重建；high contrast 只复用播放器局部主题的实色和描边策略。

## 验收重点

- 菜单从播放器右键位置出现，两个动作均可通过文本、语义和稳定 key 定位；选中后仍打开原信息/诊断层。
- 100%、125%、150% 文字缩放下菜单项可读；high contrast 使用可见描边；reduced motion 不新增位移或持续动画。
- 完成 focused/widget、全量测试、`flutter analyze`、Windows debug build 和真实播放器窗口检查；实窗验收需等待菜单
  进入动画完成后再判断文字对比度，避免把过渡帧误判为终态。
