# 播放器启动决策与能力警告 UI 外壳目标

本页是播放器 Phase 2 在信息/诊断弹窗之后的下一处内容浮层目标。继续观看选择与硬解能力警告仍由播放器启动流程提供数据和结果；本轮只统一弹窗主题、内容表面和稳定挂载证据，不改变起播选择、硬解门禁或代理命令。

## Before / After

| Before | After | Why |
| --- | --- | --- |
| 继续观看与硬解警告直接使用全局 `AlertDialog`，在播放器深色画布上可能出现主题断层 | 两类弹窗显式复用播放器局部主题和 high contrast 策略 | 让启动前的决策浮层与播放中的信息/诊断层保持连续 |
| 起播位置、硬解规格、恢复建议和操作按钮依赖默认弹窗内容节奏 | 保留原字段、文案和操作顺序，只收敛标题、正文、滚动区域和底部动作层级 | 提升扫描效率，不改变用户决策或恢复路径 |
| 弹窗根节点只有部分动作 key，页面级入口检查难以统一定位 | 增加 `player.resume.dialog`，保留硬解警告根 key 与所有动作 key | 让真实挂载、键盘焦点和回归测试共享同一定位证据 |

## 保护边界

- 继续观看仍默认在关闭或无选择时继续，保留“从头播放”和“从上次位置继续”的返回值与 autofocus。
- 硬解警告仍阻止不可靠的直接播放，保留规格、原因、代理命令、复制命令、取消播放和不可覆盖源文件的说明。
- 复制代理命令仍只写入系统剪贴板；SnackBar 文案和显示时机不变。
- 不修改 `PlaybackSession`、`PlayerBackend`、硬解兼容性评估、来源 `filtered playback queue`、播放器启动顺序、缩略图/媒体详情队列、schema、stable identity 或用户数据。
- 不新增 I/O、持久化、查询、预取、全窗口 blur 或持续动画；只复用 `playerWorkspaceTheme` 和现有无障碍策略。

## 验收重点

- 播放器启动路径中的继续观看与硬解警告仍可达；根节点、操作按钮、命令文本和取消路径均可定位。
- 100%、125%、150% 文字缩放下起播内容、硬解建议和命令文本可滚动查看，底部动作不被内容遮挡。
- high contrast 使用可见描边和不透明结构表面，reduced motion 不新增位移或持续动画。
- 完成 focused/widget、全量测试、`flutter analyze`、Windows debug build 和真实播放器窗口检查。
