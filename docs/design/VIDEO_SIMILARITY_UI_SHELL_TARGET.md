# 相似视频页 UI 外壳 Before / After 目标

## 视觉方向

相似视频页属于媒体库的维护型子流程：它负责解释重复候选和视觉复核状态，但不应看起来像
另一个独立应用。目标是把“扫描状态—候选组—人工处理动作”压缩到稳定的 Calm Desktop
Media Workspace 外壳中，让用户始终知道自己仍在媒体库维护链路内。

| Before | After | Why |
| --- | --- | --- |
| 使用普通 `AppBar`，返回和重新计算动作与目录管理、Missing/Relink 的维护上下文不一致 | 使用“维护工作区 / 相似视频”两级标题栏，返回和重新计算保留原 key、tooltip 与禁用语义 | 建立稳定来源感，减少进入扫描页后的路由迷失 |
| 结果区在宽窗口下随窗口无限拉伸，摘要与候选组的阅读线过长 | 内容区使用 1120px 桌面宽度上限，窄窗口仍按原安全边距收缩 | 让扫描摘要、缩略图、路径和行级动作处在同一可读密度 |
| 页面仅使用基础维护主题，重新计算、tooltip 和错误反馈可能跨 Route 回退到全局主题 | 页面外壳接入 `maintenanceFeedbackTheme`，继续使用实色 surface 与弱描边 | 保持扫描中、失败、重算和定位动作的反馈层级一致，不引入 blur 或持续动画 |
| 滚动条安全区虽已存在，但外壳没有明确内容边界 | 保留候选列表右侧 18px 滚动安全区，并把它纳入受限内容列 | 行内播放、删除、定位和匹配建议不被 Windows overlay scrollbar 覆盖 |

## 明确保护

- `VideoSimilarityScanController` 的 Route 级生命周期、前台/播放让渡与取消代次；
- `VideoSimilarityReport` 的确定重复、视觉候选、排序、局部删除和 stale 语义；
- `ThumbnailService` 缩略图/相似取帧队列与媒体详情，不在 UI 层新增 I/O 或扫描；
- 播放入口传入当前候选组 playlist，播放器返回后的 stable videoId 对账；
- 删除前选择保留目标、标签/收藏合并、回收站流程和用户数据；
- 重新计算、扫描中禁用、空态、错误、返回媒体库和所有既有 ValueKey/tooltip。

## 验收重点

- 100%、125%、150% 文字缩放下标题栏动作、摘要 pills、候选行和滚动安全区不溢出；
- high contrast 使用实色表面和可见描边，reduced motion 不依赖新增持续动画；
- 确定重复组、视觉近重复候选、扫描中、失败和空态均留在同一内容宽度边界；
- 页面级证据覆盖标题栏挂载、重新计算入口、结果列表 key、播放/删除/定位可达性；
- 完成 focused/全量测试、架构契约、`flutter analyze`、Windows debug build 和真实窗口检查。
