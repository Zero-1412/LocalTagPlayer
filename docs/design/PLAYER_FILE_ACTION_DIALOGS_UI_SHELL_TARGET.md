# 播放器文件动作弹窗 UI 外壳目标

本页是播放器 Phase 2 在启动浮层之后的下一处可达 UI 外壳。删除文件和重命名文件仍由播放器动作 owner 负责；本轮只统一播放器局部主题、浮层表面和挂载证据，不改变文件事务、返回值或危险动作边界。

## Before / After

| Before | After | Why |
| --- | --- | --- |
| 删除确认层使用维护页主题，重命名层在内部重复包一层主题，播放器中不同文件动作的表面来源不一致 | 删除与重命名统一显式复用 `playerDialogThemeSurface` 和播放器浮层 token | 让文件动作与视频信息、诊断、启动决策保持同一播放器空间连续性 |
| 删除影响范围、路径、偏好和动作按钮依赖默认 `AlertDialog` 内容节奏 | 保留现有影响说明、回收站语义、“不再提示”、输入校验和按钮顺序，只收敛不透明表面、描边与宽度边界 | 降低高风险操作的视觉噪声，不改变确认或撤销路径 |
| 只有输入和动作按钮有稳定 key，页面级回归无法统一确认弹窗已挂载 | 增加 `player.delete.dialog` 与 `player.renameFile.dialog`，保留原有输入、确认、取消和偏好 key | 让真实挂载、焦点路径和 focused/widget 测试共享定位证据 |

## 保护边界

- 删除仍只进入系统回收站；确认、取消和“不再提示”返回值保持不变。
- 重命名仍只返回经过校验的 basename，扩展名只读保留；磁盘和数据库事务仍由播放器外部协调。
- 不修改 `FileCommandExecutor`、稳定 `videoId`、mutable path、播放状态恢复、播放器队列、`PlayerBackend`、缩略图/媒体详情队列、schema 或用户数据。
- 不新增 I/O、查询、列表重算、预取、全窗口 blur 或持续动画；只复用播放器主题和现有无障碍策略。

## 验收重点

- 删除弹窗可定位影响说明、回收站动作、不再提示、取消和确认；重命名弹窗可定位输入、校验错误、取消和确认。
- 100%、125%、150% 文字缩放下内容与底部动作不互相遮挡；high contrast 使用实色表面和可见描边；reduced motion 不新增位移或持续动画。
- 继续通过 focused/widget、架构、全量测试、`flutter analyze`、Windows debug build 和真实播放器窗口检查。
