# 播放器信息与诊断 UI 外壳目标

本页是播放器 Phase 2 在媒体控制之后的下一处内容弹窗外壳目标。视频信息和播放诊断继续只展示当前播放器会话已经提供的数据；本轮只统一弹窗主题、分组表面和可达性标识，不改变诊断采样、复制摘要或媒体详情读取。

## Before / After

| Before | After | 目的 |
| --- | --- | --- |
| 视频信息、播放诊断的 `AlertDialog` 可能沿用全局 Route 主题，内容层与播放器画布不连续 | 两类弹窗在根部显式复用 `playerWorkspaceTheme` 和已有 high contrast 策略 | 让播放器内容浮层保持同一深色工作区层级 |
| 文件、媒体、整理状态、实时状态和详细指标分组使用匿名 `DecoratedBox` | 分组使用实色 `Material`、弱描边、统一圆角和 `Clip.antiAlias` | 让信息边界稳定，避免内容越过圆角或依赖默认卡片材质 |
| 分组没有统一的容器语义，页面级挂载检查只能依赖文案或子控件 | 分组保留标题并增加容器语义与稳定 surface key | 让读屏结构、页面可达性和视觉验收拥有同一定位点 |

## 保护边界

- 视频信息继续读取当前媒体的文件 stat、媒体详情、标签、收藏和已有错误文案；不新增读取、缓存或预取任务。
- 播放诊断继续由弹窗内部管理采样 timer、播放状态订阅、错误重试、摘要复制和 dispose 取消；本轮不改变采样频率、分析规则或隐私文案。
- 保留视频信息与诊断入口、关闭路径、滚动区域、选择/复制文本、诊断关闭和复制按钮。
- 不修改 `PlayerService`、`PlayerBackend`、`PlaybackSession`、来源 `filtered playback queue`、`FilterQuery`、`TagQueryService`、ThumbnailService、媒体详情/缓存队列、schema、stable identity 或用户数据。
- 不新增持久化、网络、文件写入、全窗口 blur 或持续动画；主题只复用现有播放器 token 和无障碍策略。

## 验收重点

- 播放器上下文菜单中的“视频信息”和“诊断检查”仍可达；两类弹窗根节点与主要分组均可通过稳定 key 定位。
- 100%、125%、150% 文字缩放与 high contrast 下，标题、分组边界、诊断详细指标和底部操作仍可滚动到；无明显遮挡、溢出或低对比度。
- 诊断弹窗卸载后不再响应播放流或遗留 timer；信息字段、诊断分析、错误/详细指标和复制摘要内容保持原顺序与语义。
- 完成 focused/widget、全量测试、`flutter analyze`、Windows debug build 和真实播放器窗口检查。
